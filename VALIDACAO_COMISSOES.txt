VALIDAÇÃO — MÓDULO DE COMISSÕES

1. Sintaxe da API
- `node --check api/data.js`: OK.

2. Sintaxe JSX
- App.jsx, Commissions.jsx e main.jsx foram passados pelo parser do TypeScript em modo JSX.
- Nenhum erro sintático TS10xx/TS11xx foi encontrado.
- O ambiente contém node_modules incompleto, então o build Vite completo não pôde ser executado localmente sem reinstalar dependências.

3. Segurança / permissões
- Criar/editar venda: requireAdmin no servidor.
- Registrar/corrigir pagamento: requireAdmin no servidor.
- Cancelar comissão: requireAdmin no servidor.
- Acesso 2: leitura filtrada pelo sellerId da sessão de estado validada no servidor.
- Auditoria financeira completa somente para administrador.

4. Concorrência / persistência
- Vendas, parcelas, pagamentos e auditoria estão em estruturas Redis separadas.
- Operações financeiras de escrita usam COMMISSION_LOCK_KEY.
- Venda + parcelas + auditoria são persistidas em MULTI.
- Pagamento + auditoria são persistidos em MULTI.
- Leituras da tela financeira usam o mesmo lock para evitar mistura de versões.

5. Retry / duplicidade financeira
- Pagamento recebe requestId único gerado no navegador.
- O mesmo requestId é reutilizado em retry automático.
- A API verifica o requestId antes de criar pagamento e retorna o já existente se a primeira tentativa tiver sido salva.
- Isso evita pagamento duplicado quando o Redis grava e a resposta HTTP se perde.

6. Comissão percentual
- Cálculo automático por percentual.
- Exceção manual opcional registrada no objeto da venda (`commissionManual`).
- Alteração estrutural é bloqueada pelo servidor depois que existe pagamento.

7. Venda semelhante
- Nova venda compara vendedor + cliente normalizado + data + valor.
- Retorna 409 se encontrar semelhante.
- O administrador pode confirmar explicitamente e reenviar com `force=true`.

8. Cancelamento
- Não apaga histórico.
- Venda fica com status cancelled.
- Pagamentos realizados continuam registrados.
- Saldo em aberto da venda cancelada não é contado como obrigação futura.

9. Backups
- O snapshot do backup inclui vendas, parcelas, pagamentos e auditoria de comissões.
- Restauração inclui as estruturas financeiras.
